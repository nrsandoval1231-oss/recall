## Objective and decision

Let a desktop user import **one `.txt` or `.md` UTF-8 file** into the selected Obsidian vault and later find it through the existing organized-memory and Ask paths. The selected file's original bytes are durably saved before any model work. Both extensions become an inert `Recall/Sources/<memory-id>.txt` attachment; the exact safe original basename/extension is retained as provenance and shown in the UI. A `.md` source is never copied into `Recall/Memories/*.md` or parsed for Recall identity, permissions, frontmatter, properties, links or tags. Recall creates its own versioned memory note. No user filing, Markdown knowledge or per-note organization approval.

Choose **v8**: add explicit `imported_text` metadata (`original_name`, `original_extension`, `source_media_type` as data, not authority) to new event/memory records, with strict validation and a v8 renderer/writer fence. Existing v1-v7 events, manifests, source paths and rendered bytes remain unchanged. The physical attachment stays `.txt` even for an imported `.md`; the original filename is separately versioned, and opening/downloading the original uses text as inert content with the original name visible. `source_kind=text` remains the organization wire kind. There is no `file` grant or broader processor. Continue to write typed text and photos on a vault whose manifest has advanced to v8; a new writer must not create v5/v2 events under a v8 manifest if that violates the established downgrade/replay rules. Carry the v8 envelope and format-aware renderer through their existing operations while preserving old records byte-for-byte.

Intake accepts at most the existing `MAX_NOTE` 256 KiB source limit and a strict, case-insensitive final `.txt` or `.md` extension. Validate a regular file through the native picker, bounded read, stable metadata and content check; refuse symlinks/reparse points, an invalid basename, NUL, invalid UTF-8, empty/whitespace-only semantic text, or changed bytes during intake. Preserve all original bytes and CRLF/LF exactly. **BOM rule:** permit one leading UTF-8 BOM in the source attachment, remove only that BOM from the semantic/human text used for the Recall note and organizer, and record both original-byte hash and semantic-text hash. A BOM elsewhere remains literal text. Never normalize line endings or interpret Markdown syntax as Recall metadata. The v8 renderer must make imported source text inert in the generated note (for example, a bounded, reversible escaped display region); its reconciliation parser must not mistake source-supplied headings/frontmatter for a Recall human correction. Only edits to Recall's own explicit human annotation region become `human:obsidian` revisions. The original stays immutable.

The organizer already has a smaller limit: text must be <=30,000 Unicode characters and <=120,000 UTF-8 bytes. A valid file above that threshold is still locally captured and searchable/openable. The existing future-only organization decision creates a `saved_local` intent with `INPUT_LIMIT_EXCEEDED`; UI says the file was saved and automatic organization was skipped because of the size. No truncation, hidden split, provider call, retry loop or false processed state. A user can make a separate smaller capture if desired. Without current remembered consent or service readiness, the file remains local and is never silently enrolled later.

## Native operation and crash contract

Expose `vault_import_text_file(expectedVaultId, operationId) -> Option<VaultMemory>`. Native owns the picker and path; renderer supplies only vault/session identity and a UUID operation ID. Before opening a picker, under the selected-vault lock, check the authoritative capture receipt and recover any pending journal for that operation. A committed receipt returns current state without reopening the file picker. A cancelled picker returns `None` and commits no receipt; the UI keeps its pending operation ID until an explicit abandon/retry choice.

After selecting, native validates and reads the file within the bound session, then reacquires the vault lock and rechecks session/receipt/current selection before writing. Before the immutable source or event write, create a **create-only import intent** under a v8 `_meta/imports/<operation-id>.json` path containing exact vault ID, operation ID, safe original name/extension, original-byte SHA-256 and length, semantic-text SHA-256 and length, and format version; no selected absolute path, credential or provider output. The intent is not a memory and is never sent to the provider. Flush it durably. Identical retry material may reuse it; changed bytes/name/vault for the same ID fail as an idempotency conflict. Snapshot the existing future-only organize consent/epoch and prepare its local operation under the current capture fence, as photo/text capture already does; no dispatch yet. Publish `Sources/<operation-id>.txt` create-only, flush, then commit the v8 journal event/note through the existing atomic writer and writer fence. Schedule only after the memory commit. The event payload digest binds all import provenance plus original and semantic hashes; the receipt returns authoritative current state.

On restart or ambiguous UI completion, native first recovers the journal/receipt. With an import intent and already published source but no committed memory, it verifies the stored bytes and intent, derives the same BOM-aware semantic text and completes **the same operation** without another picker or model call. With an intent but no source, it requires reselecting the same bytes and basename; a different selection fails clearly. Damaged source, divergent intent, unrelated vault selection or ambiguous journal state remains `UNKNOWN`/conflict for explicit recovery, never a new operation or silent replacement. Repeated operation IDs across photo/typed/file capture conflict. Abandoning a pending UI intent does not erase an already durable source or journal evidence; expose the recovery state honestly. Source-first durability, current session checks and selected-vault revalidation are mandatory before commit and organization dispatch.
