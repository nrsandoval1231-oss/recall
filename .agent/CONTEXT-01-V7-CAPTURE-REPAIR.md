# CONTEXT-01 v7 repeated-capture repair addendum

**ACTIVE bounded correction, native lane only.** The first v7 organization fences the vault manifest to v7. A later source-first capture is therefore journaled as v7 with `organization=None` and `context_link_projection=[]`. Its first valid v2 organization result may contain related targets, but `organization_transition()` currently compares the empty capture projection to the new one under the rule for an **established** proposal and rejects promotion. This blocks the normal second-and-later capture path. The issue is a transition distinction, not a new product feature.

Permit exactly one initialization transition through the existing `kind="organization"` branch when **all** are true: `prev.format == next.format == FORMAT_V7`; `prev.kind == "capture"`; `prev.memory.organization.is_none()`; `prev.context_link_projection == Some([])`; `next.kind == "organization"`; `next.memory.organization` is a valid, unsuppressed v2 proposal bound to `prev.memory` and `prev.memory.revision` by the existing organization checks; and `next.context_link_projection` is `Some(...)` with 0–3 entries whose order, target IDs, safe basenames and uniqueness match that proposal's `related_context` under the existing v7 event validator. The normal promotion path must still revalidate selected vault/session, source and every bound current target immediately before the atomic commit. This is the **first projection publication** of that captured memory, never a mutation of an earlier proposal.

For every other v7 transition, retain the existing length/target/basename equality and `suppressed:false -> true` monotonicity. In particular, `context_suppress`, human correction, external edit, remove and restore cannot insert, retarget, rename or revive a link; an existing proposal (even if later suppressed) does not gain this capture-only exception. Do not relax v7 replay/hash/parent checks, human correction precedence or v1–v6 byte compatibility. The normal event hash includes the new projection exactly as before, and historical v7 capture remains byte-exact with its empty projection.

Native acceptance: publish v7 for capture A, save capture B after the manifest fence, verify B's v7 capture event has empty projection and original saved first, then promote B's first v2 organization with one legitimate target. Reopen/recover and verify both events' journal/history/receipt/Markdown hashes and B's current link. Negative cases must reject a second insertion, retargeting, basename change, suppressed-link revival and insertion during human correction/external reconciliation. Existing v1–v6 fixtures and source-first/unknown-effect tests remain. No backend/UI wire change, live processing or native rename feature follows from this correction.
