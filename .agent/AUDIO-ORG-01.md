The new setting `RECALL_LOCAL_AUDIO_ORGANIZATION_ENABLED` defaults to **false**.

## Objective

An eligible, unreviewed machine transcript of a voice recording captured **after** the user's remembered, separate, revocable audio-organization decision is organized automatically into validated, unverified Obsidian proposals (summary, mentions, statements, action suggestions, uncertainties), with no per-note approval. Text/photo consent never enrolls audio and audio consent never enrolls text/photo. The recording itself is never sent to the provider; only the bounded transcript text is.

### Binding 3.0 (header `X-Recall-Organization: v3.<base64url-no-pad canonical JSON>`)
Same encoding rules as `v2.` (ASCII, no padding, canonical re-encode equality, <= 3072 header bytes, decoded <= 2300 bytes). Exact key set:
`schema_version:"3.0"`, `operation_id`, `vault_id`, `memory_id` (canonical lowercase UUIDs), `source_kind:"audio_transcript"`, `source_sha256` (SHA-256 of the full immutable WAV), `expected_revision` (int >=1, the memory revision the transcript belongs to), `input_sha256` (SHA-256 of the transcript UTF-8 request body), `derivative_sha256` (hash of the 16 kHz derivative that was transcribed; lowercase hex), `transcript_revision` (int >=1; revision of the machine transcript or human correction used), `transcript_evidence_kind` (`"machine_unreviewed"` | `"human_corrected"`), `consent_epoch` (audio consent epoch, int >=1), `captured_at` (same RFC 3339 rule as v1/v2). **No context fields** (related-memory context is out of scope; a context-bearing audio binding would be 3.1). Body media type must be exactly `text/plain; charset=utf-8`; body is the exact UTF-8 transcript (non-empty, no NUL, <= 30,000 characters, <= 120,000 bytes), hash must equal `input_sha256`. Versions 1.0 and 2.0 bytes/behavior unchanged.

### Provider behavior (backend)
Transcript is DATA, an **unreviewed machine transcription that may mishear or omit words** (or, for `human_corrected`, the person's corrected wording). New system prompt for audio transcripts; selected through an explicit request field (e.g. `InterpretTextRequest.source_kind`) so text behavior is unchanged. Provider returns only the existing semantic fields; every evidence quote must be an exact substring of the transcript; wrapper page `legibility` is `"mixed"` for `machine_unreviewed` and `"clear"` is **never** used for machine wording (`"clear"` allowed only for `human_corrected`). Result gets `review_state:"unreviewed"`. No `related_context`. Same budget reservation (`purpose="organize"`), `UNKNOWN`/failed handling and receipt TTL as the text path. Provider identity is Anthropic semantic provenance; it must never be described as ASR provenance.

### Native (vault + commands)
- Separate marker file (`_meta/audio-organization-marker.json`, same shape as `OrganizationMarker` with the audio policy version) set only by a confirmed audio consent decision; separate Tauri commands `vault_audio_organization_capability`, `vault_set_audio_organization_consent`, `vault_reconcile_audio_organization_consent` mirroring the existing three (same connection-fingerprint, epoch, "needs_setup/unknown/ready/off" local-readiness semantics, future-capture fence).
- At audio capture commit, if an audio marker exists, prepare a durable audio intent recording the audio consent epoch and local epoch; state `awaiting_transcript`. Original is saved first; capture never blocks on consent. No backlog enrollment; a later opt-in or epoch change never revives older intents (they go `stale`).
- When an **eligible** machine transcript commits (or a human correction replaces it), build the Binding 3.0 request from the then-current transcript (exact UTF-8 bytes), move the intent to `queued`. Ineligible/failed/UNKNOWN/oversize transcripts never queue (`saved_local` with honest code). Before the provider call and again before promotion, revalidate under the vault lock: selected vault identity, memory revision, WAV source hash, derivative hash, transcript text hash and evidence kind, human-correction absence/presence, audio marker epoch and connection fingerprint. A human correction after dispatch or promotion marks the proposal stale/suppressed in current organization/search/Ask while history retains it. Any mismatch -> `stale` with a code, never promote.
- Promotion writes a v9 journaled event projecting the validated proposals onto the audio memory (new field(s) on `VaultMemory`, e.g. `audio_organization`), rendered into the note Markdown as inert, clearly "unreviewed machine proposals derived from an unreviewed machine transcript" content; supported direct edits stay confined to the human annotation region. All v1-v9 existing events/Markdown/original bytes remain byte-identical; old writers refuse v9. Sent/ambiguous provider effects keep the existing reservation / `UNKNOWN` handling and are never blindly retried. Audio remains excluded from the context sent for other memories and receives no related-memory links in this packet.
- Audio proposals are proposals only: not verified facts, no identity links from name matches, no approval step.

### UI
A separate "Organize voice notes automatically" control (not tied to the text/photo control) in the existing maintenance/settings disclosure, with honest copy: only the transcript text of **future** recordings is sent to Claude, never the recording; the choice is remembered, revocable, does not apply to existing recordings, and requires the private service connection. States mirror the existing organization UI (off / needs setup / ready / unknown). Audio memory view shows organization results as unreviewed proposals under the transcript, and a stale/suppressed state after correction. Never imply verification.
