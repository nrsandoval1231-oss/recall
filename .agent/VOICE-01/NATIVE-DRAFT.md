## One useful path and dependency frontier

The first integrated result is **Record → Stop → vault original → actual local transcript → optional automatic organization → grounded Ask and original playback**, with one correction retaining history. A supported WAV importer may use the same path after Record/Stop works; import alone is not a voice result. Keep backend audio organization dependent on a frozen native DTO. No speculative broad file decoder, diarization, phone transport, batch import or model router.

F0 pinned whisper.cpp source commit `d1be6fde11ac6e0407606b4e42fe72d34add8037`; multilingual `ggml-base.bin` comes from Hugging Face revision `5359861c739e955e79d9a303bcbc70fb988958b1`, exactly 147,951,465 bytes, SHA-256 `60ed5bc3dd14eea856493d334349b405782ddcaf0028d4b5df4088345fba2efe`. Final static-CRT Windows CLI SHA-256 is `329c713c8b36eb8c367137d624b75ec57e17f8b3061fd823c59433abd5f76951`; the four runtime DLL and license hashes are in F0's verified artifact manifest. The *actual installed synthetic Tauri/NSIS fixture* ran the full-volume SAPI phrase exactly in 1.254 s, peak working set 317,116,416 bytes, with 123.82 MiB installer delta versus a minimal fixture. This proves neither an installed Recall build nor real microphone operation. Gain-reduced 1/2/5/10% copies (RMS 34–344) lost “at three in afternoon”; five seconds of silence yielded `you`, a tone `[Music]`, near-noise `[BLANK_AUDIO]`, and corrupt input exited 11. RMS <= 5 separated only tested zero/near-zero fixtures. Stage exactly the F0 binary, DLLs, model and notices in Recall's installer; verify the manifest at packaging and runtime. Any rebuilt binary/hash is a new candidate requiring renewed installed proof.

## Existing code constraints

`local_vault.rs` currently supports v1-v8; `VaultMemory` stores `reading` for photo Claude output and `imported_text` for v8 source files. `reading_storage.rs` explicitly rejects text for photo `Reading`, whose request/result are a photo-service binding. `event_valid`, `verify_source`, physical source path selection, replay, manifest upgrade, renderer, direct-edit reconciliation, current Ask and retained-history Ask all branch on format/source fields. The current organization wire and backend accept only `text|photo`; text is exact human-authored text. Audio must not be disguised as either photo `Reading` or typed/imported text. Current `vault_source` returns verified bytes to the renderer; it may supply a bounded WAV Blob for playback after native hash checks, but no source filesystem path or recording stream crosses that boundary.

## Native v9 candidate and operation identity

Add `recall-local-vault-v9` only for new writes after a v9 upgrade. V1-v8 events, manifests, rendered Markdown and original files remain byte-identical; old writers refuse v9. All mutation paths on a v9 manifest, including photo/text capture, import, correction, restore/remove, external edit, organization and context suppression, must retain the v9 envelope/writer fence rather than write an older event under the new manifest. Bind v9 payload digest to existing event fields **plus** audio source/transcript fields and context projection. Validate transitions so unrelated events cannot alter provenance, machine output or human correction. Preserve required provenance through `VaultRevision`, current views, export/rebuild and history.

Use separate optional fields rather than changing the photo `Reading` type:

```text
VaultMemory.audio_source?: {
  capture_origin: "recorded" | "imported_wav";
  original_name?: safe basename;  // display only; never path authority
  media_type: "audio/wav";
  source_sha256: lowercase SHA-256; source_bytes: integer;
  sample_rate_hz: 16000 | 32000 | 44100 | 48000;
  channels: 1 | 2; pcm_bits: 16; duration_ms: integer;
}
VaultMemory.audio_transcript?: {
  machine: { operation_id, source_sha256, source_revision,
    runtime_source_commit, runtime_binary_sha256, model_sha256,
    derivative_sha256, transform_version,
    output_sha256, text, optional_validated_segments,
    input_rms_pcm16, quality_flags, quality_state: "machine_unreviewed" };
  human_correction?: { operation_id, text, corrected_at };
}
```

The authoritative source hash is the hash of **the full immutable WAV file bytes**, stored at `Recall/Sources/<memory-id>.wav`. Do not replace it with resampled input or a transcript hash. The native-recorded original is a WAV of the captured device samples after deterministic PCM16 conversion at the actual selected rate/channel count; a bounded, deterministic 16 kHz mono PCM16 derivative may feed Whisper. Keep derivative hash/transform version in the ASR operation metadata. For an imported WAV, validate regular-file identity and RIFF chunks/PCM format from bytes, stable metadata, safe basename, duration and size before publishing. No `ffmpeg`, arbitrary binary path, model download or decoder fallback at runtime.

Use one stable UUID for a recording/capture receipt and separate stable UUIDs for ASR and transcript correction operations. `vault_audio_start(expectedVaultId, operationId)` creates a durable create-only intent bound to vault/session and opens a single microphone capture. `vault_audio_stop(expectedVaultId, operationId)` flushes/finalizes the staged WAV, rechecks selected vault/session, publishes the source create-only, commits a v9 `capture` event with `audio_source` and no transcript, then returns a `saved_local` memory. `vault_audio_status(expectedVaultId, operationId)` recovers receipt/stage/ASR state after lost UI acknowledgement. A duplicate start/stop returns the same receipt or conflict; it never re-records under the same ID. An optional `vault_import_wav` uses a native picker and this same source commit path. The renderer sends IDs, never file paths or microphone samples.

One native recording session at a time. Pin Windows `cpal = "=0.18.2"` (crates.io archive SHA-256 `6f02e8d0327b42d3e2e4ab2119af397344eb9fc54a34bf0ddeaa1277af8681f1`, Apache-2.0, MSRV 1.85) for WASAPI device enumeration/callbacks and `rubato = "=5.0.1"` (archive SHA-256 `cc1e951b9f5432ec1422f4dcfa5733fc501265902612edf5ef8bd8ecdd960930`, MIT OR Apache-2.0, MSRV 1.87) for its fixed-ratio anti-aliased `Fft` conversion **after capture**. These exact pins come from current crates.io metadata and primary [cpal 0.18.2 docs](https://docs.rs/cpal/0.18.2/cpal/) and [rubato 5.0.1 docs](https://docs.rs/crate/rubato/5.0.1); build still must verify lockfile/toolchain compatibility because `rustc`/`cargo` were unavailable in this architect shell. Select only an advertised 16/32/44.1/48 kHz mono/stereo input format; unsupported rate/channel or unhandled sample type gives `unsupported_device` before opening a stream. Normalize the selected `f32`, `i16` or `u16` callback samples deterministically to clipped, rounded PCM16 in their original rate/channel WAV. Capture callback only queues frames to a bounded writer; overflow/device loss stops capture with explicit failure, never silently drops frames. Cap **120 seconds or 24 MiB of PCM payload, whichever arrives first** (48 kHz stereo PCM16 is 23,040,000 bytes at 120 s); account separately for the RIFF header and bounded queue/stage memory. Auto-stop at the cap, finalize and save the valid original with a visible limit reason. Writer periodically flushes a private app-data stage with intent. Stop finalizes header/length and fsyncs file and parent before source publication. A crash before Stop leaves an explicit unfinished draft bound to its vault; recovery may finalize verified bytes for an explicit user save, but may not auto-dispatch ASR, silently discard samples or claim capture success. Vault switch/device loss prevents commit to another vault. Derive 16 kHz mono PCM16 from the finalized WAV with a frozen transform version: decode PCM16, mix stereo in fixed channel order at bounded precision, fixed-ratio anti-aliased `Fft` resample, fixed clipping/rounding and WAV serialization; hash and retain derivative provenance. Golden hashes for each supported rate/channel and chunk-boundary case prevent drift. Original/source hash remains independent of derivative hash.

## ASR and quality decision

After the capture receipt exists, native may schedule one local transcription operation. Before sidecar launch on Windows x64, require `AVX2`, `FMA`, `F16C` and `BMI2` CPU feature detection; if any are absent, retain playable original and report `transcription_unavailable: unsupported_cpu`, with no unverified fallback. Verify the packaged binary, four DLLs and model SHA-256 before launch. Invoke only a fixed native path with fixed arguments, verified derivative path in private staging, no shell string, no network, bounded output file, timeout and process kill/reap. Parse the F0-verified structured output shape; check UTF-8, text/segment bounds, monotonic offsets within audio duration, runtime/model identity and output hash. Never let CLI text choose paths, permissions, status or event kind. The ASR request binds vault ID, memory ID, capture revision, source SHA-256, derivative SHA-256, transform version, model and binary hashes; revalidate under vault lock before v9 `audio_transcription` with origin `machine:whisper-local`. Retain request/result and receipt create-only so lost completion cannot blindly rerun an ambiguous subprocess.

Source-first capture remains useful when ASR fails. F0's silent `you` proves that nonempty output is insufficient. Apply only the F0-tested **RMS <= 5 on 16-bit PCM** preflight as a zero/near-zero gate; it is neither voice activity detection nor proof that louder input contains speech. After ASR, an empty result or a result consisting only of an observed non-speech marker (`[Music]` or `[BLANK_AUDIO]`) is **ineligible** for organization/search/Ask. Corrupt input, nonzero CLI exit, malformed/out-of-duration segments, timeout, missing model and failed hash likewise remain ineligible with a visible `transcription_unavailable` state and openable original. Do not guess a broader silence, noise, tone or hallucination threshold from these fixtures. In particular, a nonempty ordinary word from noisy non-speech is not established safe by RMS; retain this as a quality risk for installed and broader held-out acceptance.

Every surviving ordinary ASR transcript is **eligible but unreviewed machine transcription**, with the verified original one click away. Failed/UNKNOWN runs, RMS-gated zero/near-zero input, empty output and sole observed non-speech markers are **ineligible**; UNKNOWN stays unresolved until reconciled. Retain input RMS and gate/result provenance, but RMS 34–344 does not establish a quiet/noisy cutoff or general voice detection. Put the concise caveat “Machine transcript may omit or mishear words; check the recording” in transcript details/source view, not a warning modal or per-recording approval. Normal eligible captures proceed to automatic organization under the separately remembered audio consent. F0 dropped a time phrase at low gain: neither native nor Claude may infer that missing time. Ask quotes only eligible transcript wording as unreviewed evidence and abstains on the absent detail. Human correction becomes current reported wording; history retains the machine version. Test quiet speech against false rejection; observed non-speech fabrication promoted into an answer is an acceptance failure. Interrupted execution remains durable and `UNKNOWN`; no blind retry.

Correction is a v9 `audio_transcript_correction` event with `human:recall` origin, `If-Match`/expected revision and stable operation ID. It preserves source/machine bytes, may deliberately replace transcript with empty text, and suppresses stale semantic proposals, current related links, search and Ask. The renderer uses a separate inert transcript region plus an explicit human annotation boundary; only supported edits inside that annotation region become `human:obsidian` revisions, never a covert transcript correction. Generated transcript/provenance edits conflict. Historical Ask retains machine wording with later human correction counterpoint under the existing paired-evidence rule; current Ask uses eligible corrected wording or abstains. A machine re-run never overwrites the human correction.

## Organization and retrieval dependent contract

Existing `OrganizationBinding.source_kind` validates only `text|photo`; backend `local_organization.py` accepts only UTF-8 text or image bytes and one current text/photo purpose consent. Freeze a **separate audio consent record and route**: migration creates `vault_intelligence_audio_organize_consents` with the same workspace/device/vault key, owner-only RLS, epoch/CAS semantics and purge revocation as `vault_intelligence_organize_consents`; route `/v1/local-intelligence/audio-organization-consent` has its own capability/decision, policy version and epoch. The v9 vault stores a separate audio consent marker/snapshot, not an overloaded text/photo `OrganizationMarker`. The provider purpose is semantic organization of an audio transcript, never upload of the WAV; the remembered decision is future-only, after original save, and changes fence queued/in-flight work. A new versioned `OrganizationBinding` **3.0** uses `source_kind="audio_transcript"`, `media_type="text/plain; charset=utf-8"`, bounded exact UTF-8 transcript body, `source_sha256` of immutable WAV, `input_sha256` of current transcript bytes, `derivative_sha256`, `transcript_revision`, `transcript_evidence_kind=machine_unreviewed|human_corrected`, expected vault revision, exact *audio* consent policy/epoch, selected context, and stable operation ID. Retain existing v1/v2 binding and routes byte-compatible. Reuse `local_organization_receipts` with binding version/source kind as discriminator and its generic `consent_policy_version`/`consent_epoch` columns; branch consent lookup by validated binding kind, never mix epochs or replay a receipt under a different purpose. Use a separate audio consent route but the existing bounded organization POST/receipt GET only after v3 validation. Backend authenticates workspace/device/vault before body/model context, enforces audio decision/budget, returns quote-validated proposals, and labels Anthropic semantic-provider provenance separately from Whisper ASR provenance. It cannot treat machine wording as deterministic human text, mark audio legibility clear by default, or promote model quotes into verified audio truth. Native rechecks vault/source/transcript/correction/audio consent immediately before promotion. Human correction or revoked/changed audio consent makes stale proposals ineligible. Text/photo consent cannot authorize audio; no backlog enrollment.

Current and retained-history Ask must include audio only after source verification and eligibility checks, with evidence kind `machine_audio_transcript`/`human_audio_correction` and epistemic state `unreviewed`/`reported`. A citation verifies revision/event hash, exact WAV source hash and quoted transcript span, opens the original via `vault_source`, and shows time offsets only if ASR segments were validated. Failed/silent/uncertain audio never enters model context. The existing `historical_texts`, `historical_counterpart_text`, current candidate selection, related-link suppression and original-source opening require explicit audio branches; a name match does not create identity links.

## Handoff and gates

Smallest frontier after accepted text baseline and F0 technical PASS: **one Luna owns native capture/source + v9 transcript/correction/Ask eligibility and frozen DTO**. Its deliverable is a bounded native candidate, never a voice-complete claim. Then a disjoint backend/contracts packet implements the separate audio consent table/route and v3 semantic wire, followed by UI Record/Stop/status/playback/correction/Ask using the frozen DTO. Integrate serially and run affected deterministic checks on the exact candidate; independent Sol review covers v9 and consent/security. Voice remains incomplete until installed Recall Record/Stop → original → real transcript → automatic organization → grounded Ask with playback is demonstrated.

Native builder packet boundary: own `apps/desktop/src-tauri/src/local_vault.rs`, a narrow new Windows recorder/ASR module, `lib.rs`/Tauri command registration, `Cargo.toml`/`Cargo.lock`, Tauri NSIS sidecar/resource manifest and native tests/fixtures only. `reading_storage.rs` may change solely for the separate v9 audio projection and v1-v8 byte regressions; it must not repurpose photo `Reading`. The packet freezes DTOs for a later UI builder. Backend migration/API/semantic provider and React files are excluded. Check crate package hashes/lockfile and compiler 1.87+ before implementation; if toolchain compatibility fails, stop that dependency choice and return a measured alternative to controller. Implement one operation/state family at a time—source journal and recorder, then deterministic conversion/sidecar/status, then correction and current/history Ask—and run focused tests between them. The native result remains unintegrated until dependent backend consent and UI packets finish; no capture-only completion claim.

Native checks: actual Windows microphone capture and permission/device-loss behavior; WAV byte/hash and vault journal replay; F0 binary/model hash; full-volume speech, the gain-reduced phrase, silence, near-noise, tone and corrupt cases with exact observed gate/status; process crash/timeout/lost reply; same/different operation IDs; source mutation, symlink import, vault switch; correction precedence; current/historical Ask source/citation integrity and abstention on the missing time; direct Obsidian edit conflict; all v1-v8 fixtures byte-identical and v9 writer refusal for old binaries. Installed-Windows acceptance must include an audible Record/Stop case and one grounded Ask opening the verified original. Fake ASR tests prove orchestration only. Record commands, exit codes, model/runtime hashes, measured latency/RAM and remaining live/phone/quality gates. A bounded engineering PASS cannot claim general accuracy or parent completion. Do not claim F0, R7A or this draft accepted before their independent evidence passes.

Remaining measured implementation gates are actual microphone permission/device behavior, lockfile/MSRV/build compatibility for the pinned crates, deterministic conversion golden hashes, v9 projection/writer coverage across existing mutations, and installed Recall integration. The architecture does not depend on an unmeasured signal-quality diagnostic beyond RMS <= 5 near-zero gating. A cloud speech provider, paid/private upload, new device association, deployment, push or merge requires separate owner authority; none is needed merely for this offline local slice.


## Controller pre-dispatch constraints

All audio commands, including status/recovery, require expectedVaultId and selected-vault/session validation before reading or exposing intents, stages, receipts or ASR state. A late result cannot cross a vault switch.

Native owns a small checked-in asset manifest and build-time staging script under scripts/, plus narrow .gitignore and Tauri bundle configuration. Generated model/binary/license staging remains ignored; verify all pinned F0 source/model/runtime/DLL/license hashes before staging. Never hardcode this machine tooling path into runtime code, download at first use, execute a user-selected binary, or silently bless newly generated hashes. Document reproducible developer preparation and truthful unsupported/non-Windows builds. Bundle dependencies beside the sidecar as established by actual Tauri F0 proof. Ordinary unit tests can inject a fixture runtime, but runtime acceptance must retain real pinned sidecar evidence.
