## Decision

Extend the existing vault Ask and its single scoped provider/receipt path to answer an **explicitly anchored historical question** from retained journal revisions. Keep current/latest questions on the accepted current Ask path. A question such as “What did I know then?” with no resolvable date or event referent returns a local clarification before any paid call: “What date or event do you mean?” The user can reply in ordinary language; there is no revision ID, taxonomy or mandatory date form. First slice resolves unambiguous calendar dates (including natural month/day/year) and local relative days such as “yesterday.” A yearless date with multiple possible years, “then,” “before that meeting,” and other unresolved event references ask a clarification; they never silently mean now. Full event-based temporal resolution remains a product requirement, not an asserted result of this packet.

“As of” means **recorded in this vault before the chosen exclusive cutoff**, not objectively true at that time. The journal's UTC `updated_at`/`recorded_at` is second-granularity and the revision sequence, not wall-clock order, decides same-second revisions. Capture time is distinct from revision recording time. If relevant event timestamps are missing, malformed or non-monotonic across a memory's revision chain, that memory is omitted with a limitation; do not interpolate. A calendar-day question uses the start of the following day in the device's explicitly displayed local timezone, converted to UTC and bound in the request. An unanchored “latest/current” uses the existing current-only path and says it is current-vault evidence.

## Source and authority boundary

Native selects under **one vault lock** after recovery and direct-edit reconciliation. It validates complete journal/history and immutable original bytes, then considers only currently active, conflict-free, source-verified memories. For a cutoff it selects the highest revision recorded before that instant. Human text and human reading corrections are the effective reading at each revision; machine readings remain labelled `unreviewed`, never promoted to verified fact. A later human correction suppresses an old machine interpretation as current semantics. If the earlier machine reading is needed to describe what Recall previously showed, include its current correction as paired counter-evidence or abstain when the bounded packet cannot fit both. A later correction to human text likewise requires a cited current counterpoint for an answer that might otherwise imply the old wording still stands. No removed/conflicted memory is resurrected as a private answer by historical selection.

Use the existing at-most-eight evidence-item, 1,500-UTF-8-byte excerpt and 32-KiB request limits. For a change comparison, two revisions of one memory may occupy two items; an as-of snapshot normally contributes one item per memory, with a current correction pair when required. If no more than eight eligible items exist, include them all. Above eight, use deterministic bounded ranking over effective historical/current text and disclose selected/eligible counts and excerpt truncation; never claim full-vault coverage. Choose a query-near exact substring on UTF-8 boundaries. No vector service, new database, background reindex or second routine provider call. A per-memory history reader alone is insufficient because calls could interleave edits; add one native selection/revalidation operation under the vault lock.

## Versioned wire and consent

Keep Ask request/receipt `1.0` byte-compatible for current questions. Historical Ask uses `schema_version: "2.0"` on the same authenticated `POST /v1/local-intelligence/ask` and receipt GET path. It adds required `temporal: {"mode":"as_of","cutoff_exclusive_utc":"2026-10-02T05:00:00Z","display_date":"2026-10-01","display_timezone":"America/Chicago"}` and adds to **each** existing evidence item `recorded_at`, `history_status` (`historical`, `current`, `later_corrected`), and `current_revision`. An as-of day cutoff is the following local midnight converted to UTC, exclusive; this handles daylight-saving transitions without an end-of-day precision assumption. For comparison with now, `temporal.mode` is `compare_to_current`, with the same cutoff fields. `citation_id` remains ordered `c1`–`c8`; identity uniqueness changes from memory ID to `(memory_id,memory_revision,evidence_kind)` so one memory can supply past and current. `coverage` counts eligible/selected **items**, not distinct memories. Backend strictly validates the v2 shape, canonical digest and all existing limits; provider packet includes `recorded_at`, `history_status`, cutoff and epistemic state. Receipt wrapper, reservation, expiry tombstone and same-operation recovery remain unchanged. The model can cite only submitted IDs; it cannot supply a path, revision, timestamp or source quote.

The current workspace Ask purpose consent covers present selected notes. Historical revision excerpts are a material data expansion. Require one explicit, remembered **Ask history** policy opt-in, for example `ask-history-v1|<existing ai_policy_version>`, on the existing Ask consent row with the same owner/device/vault grant boundary and version/epoch check. Existing consent authorizes only v1 current Ask; it does not authorize v2. A v2 decision also permits v1 current Ask, while revocation blocks both. Capability/UI names the added historic-revision sharing and the configured provider. No per-question approval. Existing rows never auto-upgrade; no new database table is required if the policy string fits the existing field. Backend must prove the request's required policy at reservation, immediately before provider dispatch, receipt return and recover; changing consent after submission must not reveal a saved result. The v2 request is still one provider call with the current budget/receipt/idempotency machinery.

## Promotion and citation

Persist the exact v2 intent before dispatch. Before sending and again before showing a recovered/completed answer, native revalidates the selected session, grant/consent, cutoff interpretation, every cited event's revision/hash/exact excerpt, current revision/state/correction and source hash. A changed current memory or correction makes the answer `stale_evidence` and requires a new operation; never silently substitute a new revision under the old receipt. Unknown provider effect recovers by the same operation ID and digest only. An empty or ambiguous date never reaches the provider.

Answer citations carry the immutable `(vault_id,memory_id,memory_revision,source_sha256,recorded_at,evidence_kind,history_status,exact quote)` from the selected packet, plus a separately recomputed **current status** when displayed. A historical note quote opens that exact retained revision next to the original attachment; it is not falsely labelled a quote from original bytes. UI wording distinguishes “Recorded then,” “Later corrected,” and “Current,” and cites both sides of a change claim. The model's historical prose is verified by the existing citation validator, with a stricter rule: any sentence asserting a change or current truth needs the corresponding past/current citations; if the answer cannot be grounded, return ambiguity/insufficient evidence and the eligible sources. Limited coverage and any excerpt truncation are explicit limitations even when the model omits them.
