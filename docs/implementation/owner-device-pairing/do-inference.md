# DigitalOcean inference service profile

`RECALL_SERVICE_PROFILE` defaults to `legacy`. That profile retains the legacy issuer, JWKS or signing-key, and signing-secret requirements. Run the inference service with the dedicated entrypoint `uvicorn recall.api.inference:app_factory --factory`. The legacy `recall.api.app:create_app` entrypoint rejects the inference profile; it never dispatches to the inference app.

The inference profile requires `DATABASE_URL`, `RECALL_AUTO_PROVISION_WORKSPACES=false`, and `RECALL_DEVICE_PAIRING_ENABLED=true`. It rejects legacy auth/signing and Supabase configuration. Provider settings are optional; without a fully configured Anthropic selection, reading returns the existing honest `AI_NOT_CONFIGURED` result. Selected-photo calls use zero retries and no refusal fallback. This profile registers only `/healthz`, `/readyz`, device-pairing routes, and selected-photo reading/recovery routes. OpenAPI, Swagger, and ReDoc are disabled. It does not construct object storage, legacy auth, capture, sync, export, or deletion services. Do not run the legacy worker in this profile; its entrypoint exits before opening storage or the database.

## Fresh operational owner

The operator bootstrap command is `python -m recall.db.inference_bootstrap --profile inference`. Set `RECALL_BOOTSTRAP_DATABASE_URL` to a separately protected, short-lived superuser or `BYPASSRLS` credential, then supply explicit stable `--owner-id` and `--workspace-id` values plus `--approve`. Never use this credential for the API or worker. Credentials must not appear in command arguments or logs. The command reads the applied migration ledger and checks the allowlisted public-table inventory and row counts in one locked transaction without applying or creating migrations. It permits the documented migration tables plus the optional pgvector `search_chunk_embeddings` table, and rejects missing or unexpected tables, foreign tables, partitions, unrelated rows, additional workspaces or memberships, and conflicting replay. Replaying the exact IDs and name before any other rows exist is a no-op. The migration ledger proves only that recorded migration checksums match the checked-in files; it does not prove the live schema, functions, triggers, grants, or RLS configuration are untampered. DO-OPS-01 must independently verify critical role ownership and privileges, forced RLS and policies, schema objects, backup/restore, and runtime connectivity before activation. Bootstrap does not take over a legacy user, provision devices, or migrate records. No real bootstrap is performed by this implementation packet.

The database should be an isolated private PostgreSQL realm on the existing DigitalOcean host. Host reachability, TLS, private networking, role separation, backup/restore, monitoring, and restore proof are operational gates for DO-OPS-01. Legacy Supabase ownership and any proposed DO database are not verified here. This profile is an implementation candidate, not activation or deployment evidence. Device enrollment, real photos, provider calls, migration, and production authorization changes remain outside this packet.
