## Findings

1. **P2 — Source and receipt actions still miss the required 48px targets.** `apps/desktop/src-tauri/src/phone/phone.css:442` applies the new minimum only to `article p a`. However `companion.js:70–73` appends “Save original copy” and “Inspect in library” directly to the article; `phone.rs:1017` renders “Open original evidence” directly under main; inferred-evidence links at `phone.rs:940` are direct li children. These important phone actions therefore remain ordinary line-height links, despite the final touch-target fix. Extend the rule to the actual action elements (or add explicit action classes), retaining sufficient separation between adjacent actions. DESIGN.md requires 48px targets where applicable. The detail screenshot visibly confirms the tight original-evidence link.

2. **P2 — View switching does not move keyboard/screen-reader focus into the new page.** `apps/desktop/src-tauri/src/phone/ui.js:16–28` hides the previous view and scrolls to the top, but leaves focus on the initiating element. A bottom-nav activation keeps keyboard focus at the end of the document, past the newly revealed form; activating a Home-card/back link hides the focused element. The page heading is neither focused nor announced. Focus the new view heading with temporary `tabindex=-1` on user navigation (without focusing an input or summoning the phone keyboard), and verify the next Tab reaches that view’s first control. Current added navigation tests use mouse clicks and do not exercise this case. This is an accessibility gap distinct from the passing axe scan.
