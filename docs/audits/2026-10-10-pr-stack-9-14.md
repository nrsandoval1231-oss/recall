## Contract checks used below

- **Platform.** One installable web app: iPhone Safari Add to Home Screen, same URL on Windows. Expo, Tauri, and NSIS are not pilot prerequisites.
- **Authority.** Cloud Postgres and private object storage stay canonical. Obsidian is an optional export.
- **Access.** No sign-in, sign-up, password, magic link, OTP, or auth callback in the user journey. An operator provisions a trusted device; the server issues a revocable device-scoped session in a Secure, HttpOnly, SameSite cookie. No anonymous access to private memory. No unrestricted token in the client, URL history, or localStorage.
- **UI.** Memory Surface in `docs/UX-SPEC.md` stays the visual authority.
- **Now.** Web-only pilot, replace email login, secure enrollment, installable PWA. Native shells are later. Reusable native code stays in the repo; it leaves the active pilot path.

Current `apps/web` still presents email sign-in (`Email me a sign-in link` in `apps/web/src/App.tsx`, Supabase callback handling in `apps/web/worker.ts`). That is the gap the next slice has to close. These PRs do not close it.

## Stack conclusions

**Merge order.** Merge #10 by itself onto `main`. Stop there. #9 is conflicting and superseded. #11–#14 are clean only against each other, in the order #9 → #11 → #12 → #13 → #14, and that order is the wrong product order.

**Obsolete relative to the Oct 9 contract.**

- #9 as an active requirements change (Obsidian required, local-first, QR still proposed).
- #11 and #12 as the pilot delivery vehicle (default local vault, Tauri, unsigned NSIS).
- #13’s binding of photo reading to that vault.
- #14’s pairing installer, compile-time origin, and separate DigitalOcean database as the way a pilot device gets in.

**Worth keeping as input, not as merges.** No-login first use (already normative on `main`). Operator-issued single-use invitation and revocable grant (#14). One-photo consent, unreviewed model output, preserved uncertainty, and human correction (#13). Image signature tests (#10).

**Next engineering slice.** On current `apps/web` only, replace the email sign-in screen and Supabase callback journey with operator-provisioned device enrollment: a single-use short-lived invitation, a server-issued revocable session in a Secure HttpOnly SameSite cookie, and negative tests for an unprovisioned browser, a revoked device, cross-workspace access, and a replayed invitation. In that same slice, add the web app manifest, icons, and standalone display on the existing Memory Surface so the same URL can be added to an iPhone Home Screen and opened in a Windows browser. Leave the #11–#14 branches in the repository and out of this slice. Do not claim that slice complete until a real provisioned iPhone and a Windows browser have been exercised; this audit does not do that.
